# Founder OS 快捷调用

## 适用场景

当你已经积累了一些长期原则、历史决定、实验结果或可复用能力，希望 AI 在处理新问题时按需读取它们，可以使用下面的快捷调用。

如果还没有建立 Router，先阅读 [公开路由系统](router-system.md)，并复制 [Founder OS Router Prompt](../prompts/founder-os-router.md)。

它适合：

- 判断一个产品或功能是否值得继续；
- 分析用户为什么需要却没有采用；
- 重新审视一个商业或资源取舍；
- 复盘一次成功、失败或准备停止的实验；
- 判断本次经验是否值得进入长期系统。

## 原始快捷提示词

```text
使用 Founder OS Router 分析下面的问题。
按需读取相关 Reference、Skill 与历史 Decision；
先解决当前问题，再判断是否值得沉淀：

[你的问题]
```

## 使用前提

这段提示词不是让 AI 凭空模拟你的判断。它需要至少能够读取下面一类材料：

- 你已经确认的长期原则或边界；
- 与当前问题相关的历史 Decision；
- 具体项目中的真实证据；
- 已经存在、适合当前任务的 Prompt 或 Skill。

如果相关材料不存在，AI 应明确说明缺口和下一项验证，不得编造历史依据或假装系统已经完成。

## 一次合格调用应该返回什么

简单问题可以自然回答，不必机械输出固定表格；但结果至少应让你知道：

- 当前问题应该怎么看；
- 依据了哪些已有材料；
- 最大取舍或不确定性是什么；
- 下一步由谁执行、验证什么；
- 结果应该留在当前项目，还是值得成为长期资产。

## 示例输入

```text
使用 Founder OS Router 分析下面的问题。
按需读取相关 Reference、Skill 与历史 Decision；
先解决当前问题，再判断是否值得沉淀：

最近有用户希望产品加入更强的自动执行能力。
这个需求技术上可以实现，但会增加权限、安全和首次理解成本。
它应该进入当前产品、延后，还是成为独立扩展？
```
